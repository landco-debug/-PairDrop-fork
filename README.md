# PairDrop Fork

Открытый форк PairDrop с исправлениями повторного сохранения, очередей передач и
нативным клиентом для MacBook с Apple Silicon. Исходная база: **PairDrop 1.11.2**,
`4862ba3067be1a0f2e0d1e94861dc9200b5bfeea`. История upstream сохранена.

## Mac-клиент: тестовая версия v3

- **Выделенный текст и ссылки:** контекстное меню → Службы → Отправить через PairDrop.
- **Файлы:** то же действие в Finder и расширение **Поделиться → PairDrop**.
- Сопряжённый получатель запоминается. Произвольному единственному соседу данные
  автоматически не отправляются. Недоступному устройству ничего не пересылается позже.
- **Закрытое окно Mac не прекращает приём.** Открыть окно можно через Finder/Launchpad;
  значок в Dock отсутствует, значок в строке меню включается отдельно.
  Открыть окно можно повторным запуском приложения. Управление — через «Меню» в окне.
- Входящие запросы файлов имеют нативные «Принять/Отклонить», связанные с конкретным запросом.
- Отправка ожидает сохранённый Android; обнаруженный раньше Chrome не заменяет получателя.
- **Нажатие на уведомление со ссылкой открывает браузер**, даже когда сообщение
  содержит подпись или строку «Источник». Нажатие на обычный текст копирует его.
- Входящие файлы сохраняются в **Загрузки/PairDrop**; уведомление показывает файл
  в Finder. Один полученный файл сохраняется один раз.
- Файлы на Mac читаются и записываются частями. Нет Electron, опроса буфера,
  целого файла в JSON или установленного приложением предела размера.

Установка не требует Homebrew, Xcode или GitHub Desktop. Нужна macOS 14+ на
Apple Silicon. Сборка имеет локальную подпись, без нотариального заверения Apple.
Старая вкладка PairDrop в Chrome — отдельный приёмник, поэтому после установки
нативного клиента её следует закрыть: иначе Android покажет оба Mac-получателя.
Регистрацию Share extension и появление Служб в конкретных приложениях ещё нужно
проверить на пользовательском Mac. Приложения с собственными контекстными меню
могут не показывать Службы.

Готовая сборка: [последние GitHub Actions](https://github.com/landco-debug/-PairDrop-fork/actions/workflows/build-clients.yml).
Архив называется **PairDrop-Fork-M1-Context-Send-Fix-v3.zip** и содержит приложение
и [инструкцию](macos/INSTALL_RU.txt). В разделе Artifacts GitHub дополнительно
упаковывает его в свой ZIP.

## Исправления веб-клиента

1. Раздельные состояния отправки и приёма; последовательная очередь исходящих наборов.
2. Автосохранение привязано к конкретному набору файлов, таймер отменяется при закрытии.
3. После сохранения диалог освобождает очередь, даже если Android-обёртка его скрывает.
4. Уведомление о полученном файле не нажимает кнопку следующего диалога.
5. HTTP(S)-ссылка извлекается из сообщения с заголовком или подписью.
6. На Mac квитанция передачи отправляется после завершения записи файла; приём
   ограничивает объём незаписанных данных ожиданием записи между разделами.
7. Отключение отменяет чтение, очищает частичные файлы и сообщает об ошибке всех
   ожидающих отправок. Повторной автоматической отправки нет.

## Android и сервер: текущая граница

**В репозитории пока нет новой Android-сборки и постоянного Android-приёмника.**
С Mac можно обмениваться данными с существующим PairDrop/Snapdrop Android-клиентом,
пока он активен. Изменения этого репозитория сами по себе не обновляют ни APK,
ни публичный сайт `pairdrop.net` на телефоне.

Mac-сборка включает исправленные веб-ресурсы и связывается с публичным сервером
сигнализации `pairdrop.net`; свой сервер для её проверки не требуется. Веб-форк
можно запускать отдельно стандартным способом upstream (`npm ci && npm start`),
но он ещё не опубликован на отдельном сервере. Оба устройства должны пользоваться
одним сервером сигнализации или соответствующей настройкой `WS_SERVER`.

Фоновый приём на Android — отдельный следующий этап: нужен явный режим приёмника,
корректная foreground-служба, уведомление и проверка Doze на A57/Android 17.
Скрытие окна и нулевое потребление ресурсов — разные требования: постоянно
доступный приёмник не может работать без процесса. Интернет-передача по-прежнему
зависит от WebRTC, NAT и доступности сервера/ретранслятора.

## Проверка и разработка

```sh
npm test
# На macOS со средствами разработчика (на пользовательском Mac это не требуется):
bash macos/build.sh
```

CI проверяет JavaScript, собирает только arm64, проверяет подпись, запись на диск
и запуск встроенного WebKit. Автоматическая проверка не заменяет реальные передачи
Mac ↔ A57 и проверку контекстных меню в Finder, Chrome и других приложениях.

Требования: [AGENTS.md](AGENTS.md). Состояние: [docs/FORK_STATUS_RU.md](docs/FORK_STATUS_RU.md).
Описание исходного проекта: [README_UPSTREAM.md](README_UPSTREAM.md).
